## Problem
Streaks were being calculated against the wrong calendar day around midnight, especially when the user was in a different timezone than the server. This caused late-night commits to be counted on the wrong day and could break otherwise valid streaks.

## Root cause
The date normalizer only understood a small set of fixed timezone abbreviations and otherwise fell back to raw UTC dates. It did not correctly convert timestamps using real timezone identifiers such as `America/New_York`.

## Fix
- Normalized timestamps through `Intl.DateTimeFormat` with the requested timezone when possible.
- Kept the old offset-based fallback for common abbreviations like `UTC`, `EST`, and `PST`.
- Returned the calendar date in the user's timezone before calculating streaks.

This keeps the daily streak anchored to the user's local day instead of the server's UTC clock.

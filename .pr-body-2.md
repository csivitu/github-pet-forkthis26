## Problem
The pet dropped to "Sleepy" immediately after a user had already been active that day, even when the streak was still alive and no new GitHub events were returned during the sync.

## Root cause
The mood logic only considered newly earned XP when deciding whether the pet should be happy. A positive streak by itself was ignored, so a live streak could be downgraded to Sleepy during a no-op sync.

## Fix
- Kept the existing priority order for Motivated, Excited, and Happy.
- Treated any active streak as a sign of recent progress, even when the current sync returned zero new XP.
- Left the fallback mood as Sleepy only when the streak is empty and there are no recent contributions.

This keeps the pet feeling active throughout the day, instead of forgetting recent work after a routine sync.
